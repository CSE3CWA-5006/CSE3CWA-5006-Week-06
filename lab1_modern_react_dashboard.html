Lab 1: Modern React Dashboard (Frontend)

 

Who does this lab?

This lab is for both CSE3CWA and CSE5006 students. Everyone completes Lab 1 and Lab 2. 

This lab uses the modern_react_dashboard project. It is a pure frontend application built with React and the Vite development server. You will not change any code in this lab. The goal is to install it, run it, and understand exactly how data flows from a data file, through React state, into the visible interface, and how the interface reacts when you interact with it.

By the end you should be able to explain, in your own words, the path: data file → custom hook (state) → App coordinator → components → rendered UI, and what re-renders when you type, filter, or click.

Part 1: Install the required software (from zero)

You will work in Ubuntu. Open a terminal with Ctrl + Alt + T. Every command below is typed into this terminal and run by pressing Enter.

Step 1.1 — Check whether Node.js is already installed

React and Vite run on Node.js. First check if you already have it:

node -v
npm -v

If both lines print a version number (for example v20.11.1 and 10.2.4), Node.js is installed and you can skip to Step 1.3. If you see command not found, continue to Step 1.2.

Step 1.2 — Install Node.js 20 LTS (only if missing)

Install Node.js 20 LTS from the official NodeSource repository:

curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

Then check the versions again with node -v and npm -v. You should now see version numbers.

Step 1.3 — Install Git (used to download the code)

Check for Git, and install it if needed:

git --version
# if missing:
sudo apt update
sudo apt install -y git

Part 3: Run the React dashboard

Move into the dashboard folder and start it with the supplied helper script. The script installs the npm packages the first time, then starts the Vite development server.

cd modern_react_dashboard
chmod +x run_ubuntu.sh
./run_ubuntu.sh

If you prefer to run the steps yourself instead of the script, these two commands do the same thing:

npm install
npm run dev

When the server is ready, the terminal prints a local address. Open it in your browser:

http://localhost:5173
 

What is Vite?

Vite is the development server and build tool for this project. When you run npm run dev, Vite serves the app at localhost:5173 and watches your files. It also provides hot reload: if a file changes, the browser updates almost instantly without a full reload. You will see this in action in the optional step at the end.

Part 4: Use the dashboard and watch the data appear

When the page first loads, notice that it shows a brief loading state before the project cards appear. This is intentional: the demo simulates a slow data load (about 0.65 seconds) so you can see the loading state that real applications need.

Once loaded, the page shows:

  • A sidebar and a top bar (the page frame).
  • Three metric cards: total projects, visible projects, and average progress.
  • A filter bar: a search box, a status dropdown, and a "Simulate error" button.
  • A list of project cards on the left and a detail panel on the right.

Now interact with it and observe the result of each action:

  • Type in the search box (for example library). The visible cards shrink to only matching projects, and the "Visible" metric updates.
  • Choose a status in the dropdown (for example At risk). Only projects with that status remain.
  • Click a project card. The detail panel on the right updates to show that project, and the clicked card becomes highlighted.
  • Click "Simulate error". A red error box appears with a Dismiss button. Click Dismiss to clear it.
  • Search for something that does not exist (for example zzz). An empty state message appears instead of cards.

Part 5: Understand the data flow (no code changes)

This project has no backend and no database. The data lives in a JavaScript file and is loaded into React state. Follow the path below by opening each file. In Ubuntu you can read any file with a native editor; you do not need to change anything.

Step 5.1 — Open files with a native Ubuntu editor

You can use vi (advanced) or the simpler nano from the terminal, or the graphical gedit/Text Editor. To just read a file without an editor, use cat or less:

# print a file to the screen
cat src/data/projects.js

# read a file page by page (press q to quit)
less src/hooks/useProjects.js

# open in nano (press Ctrl+X to exit), or vi (press :q then Enter to exit)
nano src/App.jsx
vi src/App.jsx

If you are new to these editors, the official guides are helpful: nano at https://www.nano-editor.org/docs.php, and vi/Vim at https://www.vim.org/docs.php. For beginners, nano is the easiest: the shortcuts are shown at the bottom of the screen (^X means Ctrl + X).

Step 5.2 — Follow the data from source to screen

Open the files in this order and match each one to what you saw on screen.

1. The data source: src/data/projects.js. This is the starting point of all the data. It exports an array called projectData. Each project has fields such as name, owner, status, category, progress and priority. These are exactly the values you see on the cards.

2. The state and logic: src/hooks/useProjects.js. This custom hook loads the data into React state and holds everything that changes. The simulated load uses a timer before the data appears:

useEffect(() => {
  const timer = window.setTimeout(() => {
    setProjects(projectData);
    setSelectedId(projectData[0]?.id ?? null);
    setIsLoading(false);
  }, 650);

  return () => window.clearTimeout(timer);
}, []);

The visible list is derived from the data plus your search and filter, not stored separately. This is why the cards update instantly when you type:

const filteredProjects = useMemo(() => {
  const normalisedQuery = query.trim().toLowerCase();
  return projects.filter((project) => {
    const matchesStatus = statusFilter === "All" || project.status === statusFilter;
    const matchesQuery =
      normalisedQuery.length === 0 ||
      project.name.toLowerCase().includes(normalisedQuery) ||
      project.owner.toLowerCase().includes(normalisedQuery) ||
      project.category.toLowerCase().includes(normalisedQuery);
    return matchesStatus && matchesQuery;
  });
}, [projects, query, statusFilter]);

3. The coordinator: src/App.jsx. This file does not own the detailed logic. It asks the hook for the current data and functions, then passes the right values down to each component:

const {
  projects,
  filteredProjects,
  selectedProject,
  query,
  setQuery,
  statusFilter,
  setStatusFilter,
  selectedId,
  setSelectedId,
  isLoading,
  error,
  simulateError,
  clearError
} = useProjects();

4. The components (in src/components/):

  • AppShell.jsx — the sidebar and top bar frame.
  • MetricCard.jsx — one summary metric (used three times).
  • FilterBar.jsx — the search box and status dropdown.
  • ProjectCard.jsx — one project in the list.
  • ProjectDetail.jsx — the detail panel on the right.
  • StateMessage.jsx — the loading, empty and error states.
Step 5.3 — Trace one interaction end to end

Take "clicking a card" and follow it through the code:

  • In App.jsx, each ProjectCard receives an onSelect function set to setSelectedId.
  • In ProjectCard.jsx, clicking the card calls onSelect(project.id). The card does not change the detail panel directly.
  • That updates the selectedId state inside the hook.
  • React re-renders. App.jsx recalculates selectedProject and passes it to ProjectDetail, which now shows the new project.

This is the core React idea: you do not edit the page directly; you change state, and React re-renders the UI from the new state. The data flow is one direction: data → state → components → screen, and user actions flow back up through callbacks to change state.

Part 6: Inspect the live data in the browser (developer view)

Real developers inspect a running page with the browser developer tools. You will only look; you will not change code.

  • In the browser on http://localhost:5173, press F12 (or right-click the page and choose Inspect) to open the developer tools.
  • Open the Elements tab. Hover over the HTML and watch the matching part of the page highlight. Find a project card in the HTML and see its text matches a project in projects.js.
  • Open the Network tab, then refresh the page with F5. Because this project has no backend, you will see it load JavaScript and CSS files but no API/data request — the data is built into the JavaScript bundle. This is an important observation: it confirms the dashboard is frontend-only.
  • Open the Console tab. If you click "Simulate error" on the page, the error is shown in the UI (not hidden in the console) — that is the deliberate design of a user-facing error state.
Confirm there is no backend API with curl

curl is a command-line tool that sends an HTTP request and prints the raw response. Developers use it to talk to servers and APIs without a browser. It is normally pre-installed on Ubuntu; check, and install it if needed:

curl --version
# if it is missing:
sudo apt install -y curl

With the dev server running, ask the server for the home page. Because this is a frontend-only project, the server returns an HTML page, not JSON data:

# the dev server returns an HTML document (you will see <!doctype html> ...)
curl http://localhost:5173

# show only the response headers; content-type is text/html, not application/json
curl -I http://localhost:5173

Compare this with Lab 2 and Lab 3, where the same curl command against an API endpoint returns JSON data. That contrast is the practical difference between a pure frontend (this lab) and a backend that serves data. There is no CRUD API to test here because the dashboard has no backend — its data lives inside the JavaScript bundle.

Part 7 (optional): See Vite hot reload

This step lets you watch the data-to-UI link, but it is optional and is the only place you touch a file. Keep the server running. Open the data file:

nano src/data/projects.js

Copy one project block, paste it as a new entry, give it a new id number and a different name, then save (in nano, Ctrl + O, Enter, then Ctrl + X). Switch to the browser. Vite hot-reloads automatically and the new card appears, and the "Projects" metric increases by one. This proves the screen is a direct function of the data. You can undo your change afterwards.

How to stop the server

Go back to the terminal running the server and press:

Ctrl + C

To run it again, use ./run_ubuntu.sh from the modern_react_dashboard folder.

Completion checklist

  • You can demonstrate search, status filter, card selection, the simulated error, and the empty state.
  • You can name the file that holds the data (src/data/projects.js), the file that holds the state (src/hooks/useProjects.js), and the coordinator (src/App.jsx).
  • You can explain, in one sentence, why clicking a card changes the detail panel (state changes, React re-renders).
  • You used the browser Network tab to confirm there is no backend request.
